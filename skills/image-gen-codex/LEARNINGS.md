# Image Gen via Codex — Learnings

Reproducible Codex/`$imagegen` quirks and recovery steps. Append dated, evidence-backed entries as you find new ones.

- **Codex CLI lives in a versioned directory.** The Codex desktop app installs its CLI under a versioned path (on Windows, `%LOCALAPPDATA%\OpenAI\Codex\bin\<version>\codex.exe`), so discovery must scan for the newest executable rather than hard-code the current folder. `generate.py` does this; also honors `codex` on PATH and an explicit `--codex`.
- **Built-in `$imagegen` saves to a private cache first.** It writes its raw result under a Codex user cache (e.g. `~/.codex/generated_images/...`); the task must explicitly copy the selected image into the project before returning. The bridge enforces this by requiring a `RESULT: <exact output path>` line and then validating that file.
- **Codex CLI `-i/--image <FILE>...` is variadic.** If a positional prompt is appended after one or more `--image` values, Codex consumes the prompt as another image argument and exits with `No prompt provided`. The bridge pipes the prompt through **stdin** whenever references are attached, so the prompt can never be swallowed.
- **Reference images guide, they do not pixel-lock.** A live reference-backed edit followed the source composition but changed the canvas dimensions and introduced slight tonal variation in an ostensibly flat fill. Treat references as guidance; exact product placement, geometry, flat fills, and typography require deterministic composition (compose those elements yourself over a model-generated plate).
- **Prompt encoding.** Codex reads stdin as UTF-8. This bridge sends stdin with an explicit `encoding="utf-8"`, so prompts may contain any Unicode on any OS. (If you run an older build of this bridge, or a Codex variant that reads stdin in the system locale, keep prompt files ASCII-only to avoid a `input is not valid UTF-8` / cp1252 failure on Windows.)
- **Concurrency is safe.** The bridge tolerates several concurrent invocations from one shell (proven on multi-image batch runs). Each job writes its own `--output`/manifest and a private stdin temp, so there are no cross-job collisions. Pattern: fan out independent "base" images together, then the "derived" partners (each `--image`-referencing its base) together. Keep before/after pairs linked by deriving the partner from the base, never generating them independently.
- **Do not self-composite a third-party trademark.** A creative that composited an official retailer logo (correct pixels) onto a brand-colored backdrop read as inauthentic and misrepresented that brand's usage standards. Lesson: reference outside brands as plain text only; any self-assembled third-party-trademark treatment is a misrepresentation risk regardless of pixel accuracy (see Hard Rule 0).
