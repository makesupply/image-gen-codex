# Image Gen via Codex — Learnings

Reproducible Codex/`$imagegen` quirks and recovery steps. Append dated, evidence-backed entries as you find new ones.

- **Codex CLI lives in a versioned directory.** The Codex desktop app installs its CLI under a versioned path (on Windows, `%LOCALAPPDATA%\OpenAI\Codex\bin\<version>\codex.exe`), so discovery must scan for the newest executable rather than hard-code the current folder. `generate.py` does this; also honors `codex` on PATH and an explicit `--codex`.
- **Built-in `$imagegen` saves to a private cache first.** It writes its raw result under a Codex user cache (e.g. `~/.codex/generated_images/...`); the task must explicitly copy the selected image into the project before returning. The bridge enforces this by requiring a `RESULT: <exact output path>` line and then validating that file.
- **Codex CLI `-i/--image <FILE>...` is variadic.** If a positional prompt is appended after one or more `--image` values, Codex consumes the prompt as another image argument and exits with `No prompt provided`. The bridge pipes the prompt through **stdin** whenever references are attached, so the prompt can never be swallowed.
- **Reference images guide, they do not pixel-lock.** A live reference-backed edit followed the source composition but changed the canvas dimensions and introduced slight tonal variation in an ostensibly flat fill. Treat references as guidance; exact product placement, geometry, flat fills, and typography require deterministic composition (compose those elements yourself over a model-generated plate).
- **Prompt encoding.** Codex reads stdin as UTF-8. This bridge sends stdin with an explicit `encoding="utf-8"`, so prompts may contain any Unicode on any OS. (If you run an older build of this bridge, or a Codex variant that reads stdin in the system locale, keep prompt files ASCII-only to avoid a `input is not valid UTF-8` / cp1252 failure on Windows.)
- **Concurrency is safe.** The bridge tolerates several concurrent invocations from one shell (proven on multi-image batch runs). Each job writes its own `--output`/manifest and a private stdin temp, so there are no cross-job collisions. Pattern: fan out independent "base" images together, then the "derived" partners (each `--image`-referencing its base) together. Keep before/after pairs linked by deriving the partner from the base, never generating them independently.
- **Do not self-composite a third-party trademark.** A creative that composited an official retailer logo (correct pixels) onto a brand-colored backdrop read as inauthentic and misrepresented that brand's usage standards. Lesson: reference outside brands as plain text only; any self-assembled third-party-trademark treatment is a misrepresentation risk regardless of pixel accuracy (see Hard Rule 0).
- **The macro skin formula transfers to GPT-Image, and hair is where the old phrasing failed hardest** (8-image A/B validation, 2026-09-03; details in `references/realism-formula.md` §12). Raking side-top 45-degree light plus a pore / vellus / sebum / subsurface inventory, film grain said once, zero digital sharpening, lifted blacks, soft highlight rolloff, and a prose Avoid line beat the earlier `prompt-craft` §4 phrasing on every pair at macro and close-up distance. "Individual hair strands catching light" alone produced glossy helmet hair with a painted part line, and the words "matte clay" were ignored without finish physics; the Hair Realism Block fixed it in one pass. "Dry, diffuse, no wet shine" still left a satin sheen; add "chalky, light-absorbing, no highlight on any individual strand" for a fully matte read.
- **Macro language at selfie distance is wasted, not harmful.** The full macro inventory written into a half-body selfie prompt was mostly ignored (no leather skin) and the frame drifted *more polished*, because the phone-artifact words (sensor noise, motion softness, washed grade, wide-angle arm distortion) were missing. At selfie distance those words carry the realism; the pore words do nothing. Pick the distance rung first (`realism-formula.md` §4).
- **Output size follows the prose aspect but not always the stated pixels.** Four "4:5, 1080x1350" asks came back exactly 1080x1350; four "1:1, 1024x1024" asks came back 1024x1024 twice and 1254x1254 twice. Read the manifest, never assume the size. Two 4-wide concurrent waves finished in about five minutes with no rate-limit errors.
- **Codex's built-in image generation is documented as `gpt-image-2`, with no exposed controls** (OpenAI Codex docs, read 2026-09-03 via desk research). It is invoked by natural language or `$imagegen` and draws on general Codex usage limits; there are no desktop fields for size, quality, input fidelity, reference count, masks, quotas, or concurrency. So a prose-stated size is a request, not a parameter; the exports above remain unexplained by any public source, and the manifest (prompt + actual width / height + SHA-256) is the record.
- **Say what you want, not what you do not want.** Controlled research on the DALL-E 3 lineage found plain negation handled poorly. Every constraint that matters goes into the prompt body as a positive physical state (`one small natural catchlight`, `raking side-top light`); the Avoid line only echoes it (`realism-formula.md` §8).
- **Prompt-only preservation leaks on edits; composite to enforce it.** Text-guided GPT editing alters irrelevant regions, and Codex exposes no mask. For "add fine texture, change nothing else" passes, enumerate every preserved region in the prompt, then composite only the accepted region over the original locally (`realism-formula.md` §9a). Everything outside the mask is the original by construction.
